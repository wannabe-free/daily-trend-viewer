# 데일리 트렌드 뷰어

유튜브 인기 동영상·쇼츠·인스타 릴스와 AI 영상 소식을 카테고리별 × 조회수순으로 매일 확인하는 로컬 웹사이트입니다.
API 키 없이 동작하며, 외부 패키지 설치도 필요 없습니다(파이썬 표준 라이브러리만 사용).

## 🌐 웹 버전 (설치 불필요)

**https://wannabe-free.github.io/daily-trend-viewer/**

GitHub Actions가 매일 오전 7시(한국 시간)에 수집을 시작해 GitHub Pages로 배포하는 스냅샷 버전입니다. 수집·배포가 끝나면 사이트에 반영됩니다.
- 구성: `collect.py`(수집·정적 사이트 생성) + `static_shim.js`(API 호출을 JSON 파일로 변환) + `.github/workflows/pages.yml`(매일 실행)
- 예약은 `0 22 * * *`(UTC 기준 매일 22:00 = 다음 날 한국 시간 07:00)입니다. GitHub 사정으로 시작이 지연될 수 있습니다.
- 자동 실행은 하루 한 번이며, 코드 push로는 실행하지 않습니다. 필요하면 Actions에서 수동 실행할 수 있습니다.
- 수집 실패 시 이전 데이터를 가져올 주소는 워크플로의 `PAGES_BASE`로 본인 Pages 주소를 지정합니다.
- 실시간 기능(검색, 새로고침, 계정 추가/삭제, 좋아요순 정렬)은 웹 버전에서 비활성화됩니다
- 인스타그램 등 일부 소스는 GitHub 서버 IP를 차단해 웹 버전에서 비어 있을 수 있습니다 — 전체 데이터는 아래 로컬 실행 버전을 사용하세요

### 내 GitHub Pages 활성화

1. 수정한 파일들을 `wannabe-free/daily-trend-viewer` 저장소의 기본 브랜치 `main`에 반영합니다.
2. 저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다. 배포 워크플로는 이미 있으므로 새 템플릿은 만들지 않습니다.
3. **Actions** 탭에서 Fork의 워크플로 활성화 안내가 나오면 활성화합니다. `트렌드 수집 및 Pages 배포`가 비활성 상태라면 **Enable workflow**를 누릅니다.
4. **트렌드 수집 및 Pages 배포 → Run workflow → main → Run workflow**로 최초 배포를 실행합니다.
5. 실행이 성공하면 **Settings → Pages → Visit site** 또는 https://wannabe-free.github.io/daily-trend-viewer/ 에서 확인합니다.

로컬 폴더의 수정은 GitHub에 자동 반영되지 않습니다. 웹 업로드 시 `.github/workflows/pages.yml`의 경로를 유지하세요. `reels_accounts.json`도 함께 반영해야 웹 버전에 구독 계정이 적용됩니다.

## 실행 방법

```bash
python3 ~/trend-viewer/server.py
```

브라우저에서 **http://localhost:8778** 접속

## 기능

- **유튜브 / 쇼츠 탭**: 카테고리(전체·AI 활용·AI 툴·자기계발·콘텐츠 제작·재테크·부업·경매) × 기간(오늘/이번 주/이번 달) 필터. 각 카테고리의 키워드 4~5개를 따로 검색해 중복을 제거하고 조회수순으로 합칩니다. AI 활용은 업무·자동화·콘텐츠·문서 실습, AI 툴은 도구 추천·무료 도구·사용법 중심입니다. **접이식 정렬 메뉴로 조회수순/좋아요순 전환**(좋아요는 영상마다 서버가 조회해 보강), 카드 클릭 시 팝업 재생
- **🤖 AI 영상 탭**: 새로 나온 영상 생성 모델 + 트렌딩 모델(Hugging Face 실시간)과 국내·해외 AI 영상 뉴스(구글 뉴스 RSS)를 표시합니다. 실사용 영상은 유튜브·쇼츠의 'AI 활용' / 'AI 툴'에서 봅니다.
- **🔍 검색창**(헤더): 유튜브를 임의 키워드로 검색해 조회수순으로 표시. 검색 시 영상 탭으로 전환되며, 카테고리 클릭으로 검색 해제
- **📸 릴스 탭**: `reels_accounts.json`의 33개 구독 계정에서 릴스를 수집하고 카테고리 키워드로 필터링합니다. **접이식 정렬 메뉴로 좋아요순/댓글순 전환**. 계정명을 누르면 인스타그램으로 이동하며, 로컬 버전에서는 계정을 추가/삭제할 수 있습니다. 과거 스냅샷에서도 현재 등록된 계정만 표시합니다.
- **𝕏 트위터 탭**: 트위터 임베드용 공개 API(무인증)로 구독 계정들의 최신 트윗을 참여수와 함께 수집. **접이식 정렬 메뉴**로 좋아요·댓글·리트윗·조회수순 전환. 계정 추가/삭제 가능(`x_accounts.json`). 기본 계정: OpenAI·Runway·Kling·DeepMind·Midjourney·Luma·Pika·HeyGen·ElevenLabs·Meta AI
- **🧵 스레드 탭**: 인스타그램(메타) 백엔드로 로그인 없이 실시간 조회를 시도. 메타가 조회를 막은 경우(현재 기본 상태) 각 계정 바로가기로 자동 폴백. 접이식 정렬 메뉴(좋아요·댓글·리포스트순) 제공, 계정 관리 가능(`threads_accounts.json`)
- **🎵 틱톡 탭**: tikwm 무료 공개 API로 **실시간 인기 피드(한국)+구독 계정 최신 영상**을 조회수·좋아요·댓글까지 수집. **접이식 정렬 메뉴로 조회수순/좋아요순/댓글순 전환**. 계정 추가/삭제(`tiktok_accounts.json`). 기본 계정: openai·runwayapp·krea.ai·elevenlabs·sora·zachking·khaby.lame·google
- **캐시**: 결과는 1시간 캐시되며, 우측 상단 새로고침 버튼으로 즉시 갱신 가능

## 참고 사항

- 유튜브·쇼츠의 검색 키워드는 `server.py`의 `CATEGORIES`에서 수정합니다. AI 활용: AI 활용법·챗GPT 활용법·AI 업무 자동화·AI 영상 만들기·AI 프롬프트 / AI 툴: AI 툴·무료 AI 툴·AI 툴 추천·AI 도구 추천·챗GPT 사용법 / 자기계발: 자기계발·습관 만들기·시간 관리·독서 / 콘텐츠 제작: 콘텐츠 제작·영상 편집·쇼츠 만들기·릴스 제작 / 재테크: 재테크·ETF 투자·절약·자산 관리 / 부업: 직장인 부업·블로그 수익화·디지털 노마드·온라인 부업 / 경매: 부동산 경매·경매 권리분석·경매 입찰·경매 임장. AI 검색 결과는 제목의 AI/도구명과 활용·제작·사용법 단서를 확인하고 일반 음악이나 IPO·주가 뉴스 등 검색 잡음을 제외합니다. 릴스는 별도의 `REELS_CATEGORIES`를 사용합니다.
- 릴스는 기존 카테고리에 GPT 활용·미리캔버스·블로그·맛집·여행을 제공합니다. `reels_account_info.json`의 계정 분야 태그 또는 영상 설명·계정명·프로필 키워드로 필터링합니다(인스타그램 전체 키워드 검색은 아님).
- 기존 13개 계정과 검증한 레퍼런스 20개를 포함합니다. 선정 기준은 팔로워 1만 이상, 고정 영상을 제외한 최근 릴스 6개(공개 통계 최소 4개)의 `(좋아요+댓글)/팔로워` 중앙값 1% 이상 또는 `조회수 중앙값/팔로워` 30% 이상입니다. 확인일·통계·표본 링크를 `reels_account_info.json`에 기록했고 화면의 **추가 레퍼런스 선정 근거**에서도 확인할 수 있습니다. 블로그 및 지역 맛집 계정은 인스타그램 검색 상위 12개 게시물에서 후보를 찾고, 검색어와 확인 당시의 게시물 위치를 함께 기록했습니다. 숨김 통계와 저장·공유 수는 제외하며, 자료 요청 댓글과 광고 게시물도 포함하므로 자연 참여를 보증하는 지표는 아닙니다.
- 로컬 릴스 실시간 수집이 실패하면 현재 구독 계정에 해당하는 `seed/reels.json`을 표시합니다. 저장 데이터임을 화면에 알리고 원래 수집일을 표시합니다.

- 유튜브 데이터는 내부 검색 API(InnerTube)를 조회수순 정렬로 호출해 가져옵니다. 유튜브의 공개 인기 급상승 피드는 2025년에 폐지되어 검색 기반으로 구성했습니다.
- 인스타 릴스: `instagram_reels.py`가 공개 릴스 탭과 개별 릴스 페이지에 포함된 JSON에서 계정당 6개의 실제 영상·설명·썸네일·공개 통계를 읽습니다. 로그인·쿠키·유료 API는 사용하지 않습니다. 영상은 사이트 안에서 재생하며, 재생 주소가 만료되면 공식 임베드로 전환합니다. 숨김 통계는 표시하지 않습니다.
- 릴스는 현재 수집분에 없는 계정만 이전 배포/시드에서 보완하고, 저장 영상임을 표시합니다. 기본 목록의 모든 계정에 재생 URL과 저장된 썸네일이 있는지 검증하며, 검증 실패 시 빈 결과를 배포하지 않고 작업을 실패시킵니다. 테스트: `python -m unittest -v test_instagram_reels.py`.
- 정적 배포는 실제 MP4를 `media/`에 보관해 CDN 서명 주소가 만료돼도 사이트에서 재생됩니다. MP4 합계는 920 MiB, 개별 파일은 64 MiB로 제한해 Pages 전체 용량을 관리합니다. GitHub 서버에서 새 수집이 제한되면 이전 배포의 영상 파일을 유지하며, 새 수집 시각으로 오인하지 않도록 이전 수집 계정 안내를 표시합니다. 최신 영상의 자동 수집까지 보장하는 구성은 아니며, 로컬 수집본은 `python update_seed.py`로 갱신할 수 있습니다. 계정 수와 관계없이 전체를 수집하며 어느 계정이라도 비면 기존 시드를 유지합니다.
- X(트위터): syndication 타임라인 API가 막혀 **nitter RSS**(트윗 목록, `NITTER_INSTANCES` 순서로 시도) + **트위터 임베드 CDN**(`cdn.syndication.twimg.com/tweet-result`, 트윗별 본문·좋아요·댓글·미디어) 조합으로 가져옵니다. 리트윗·조회수는 이 경로에 없어 0으로 둡니다.
- 스레드: GraphQL 무인증 조회(`THREADS_DOC_IDS`에 유효한 doc_id 필요)를 먼저 시도하고, 막히면 **RSSHub 공개 인스턴스**(`RSSHUB_INSTANCES`)로 최신 글(본문·이미지·링크)을 가져옵니다. RSS에는 통계가 없어 좋아요 등은 표시되지 않으며, 그마저 막히면 계정 바로가기로 폴백합니다.
- 웹 버전(collect.py)은 수집이 실패한 소스에 한해 **이전 배포 스냅샷을 재사용**하므로, 일시적 차단이 있어도 데이터가 사라지지 않습니다.
- 틱톡은 자체 웹/모바일 API가 서명(X-Bogus·msToken)과 TLS 지문 검사를 요구해 직접 무인증 호출이 막힙니다. 대신 **tikwm 무료 공개 API**(`www.tikwm.com/api`)가 서명을 대신 처리해 조회수·좋아요·댓글·썸네일·영상URL을 반환합니다. 무료 티어라 동시성이 높으면 일시 제한될 수 있어 서버는 낮은 동시성(3)으로 호출하고 1시간 캐시합니다. 썸네일(tiktokcdn)은 서버 이미지 프록시(`/api/img`, 메모리 캐시)로 전달합니다.
